## Compensation

Compensation requests describe work already delivered and ask stakeholders to authorize BSQ issuance. Discuss scope, review capacity and any expected compensation before substantial work. Bisq has temporarily paused accepting new contributors for compensated development; that is not a blanket ban on all contributions. See the [contributor guide](../../contribute/getting-started/) and [current policy](https://bisq.network/blog/open-source-development-in-the-age-of-ai/). A request, prior discussion or a merged change does not guarantee payment.

The recovered process described these steps:

1. Open an issue in the [compensation repository](https://github.com/bisq-network/compensation/issues), using the relevant request format and cycle information.
2. List delivered work with links to the actual changes, review, discussions and other evidence. Explain its value and how the amount was calculated. Separate different kinds of work and address feedback.
3. Check the announced cycle deadline and BSQ/USD conversion guidance. A historical convention used a 30-day volume-weighted rate and sought review a week before the proposal phase ended; do not assume either timing or rate is unchanged.
4. During the proposal phase, use `DAO` > `Governance` > `Make Proposal` and select the compensation request type. Enter the issue information and the amount, confirm fees and required BTC in the application, and submit.
5. Add the resulting BSQ transaction ID to the issue so reviewers can connect the on-chain request with the work. Track the vote and result.

## Reimbursement

A reimbursement request is distinct from ordinary compensation. First pursue the available trade and dispute process, and consult the current [dispute guidance](../../bisq-1/dispute-help/). The recovered procedure described escalation, documenting the loss, finding the published time-locked payout transaction ID where applicable, opening a reimbursement issue, submitting a DAO reimbursement proposal and linking its BSQ transaction ID back to the issue. Do not publish private payment details, logs, addresses or trade data simply because an old checklist requests them; share only necessary information through an agreed channel.

The old guide mentioned a three-month deadline and subsequent BSQ sale. Those are historical instructions, not a determination of present eligibility, payment or timing. Ask current support and inspect the [support issue tracker](https://github.com/bisq-network/support/issues) and current DAO rules before acting. A vote can reject a request.
