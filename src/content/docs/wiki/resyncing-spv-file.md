<div class="wiki-recovered-article" lang="en"><p><strong>Resyncing the SPV file</strong> (Simplified Payment Verification file, `bisq.spvchain`) can often solve wallet issues within Bisq, such as an incorrect balance showing, missing transactions, or other synchronization problems.</p>&#10;<h2 id="how-to-resync-the-spv-file"> How to Resync the SPV File </h2>&#10;<p>It is generally best to initiate an SPV file resync using the button within the Bisq application interface. However, if Bisq cannot start properly, you may need to initiate it manually via the file system.</p>&#10;<h3 id="from-the-bisq-interface"> From the Bisq Interface </h3>&#10;<p>This is the recommended method if Bisq is operational.</p>&#10;<ol>&#10;<li>Go to `Settings` &gt; `Network Info`.</li>&#10;<li>Click the `RESYNC SPV WALLET` button.</li>&#10;<li>Bisq will prompt you to restart the application <strong>twice</strong>. Follow the prompts carefully.</li>&#10;</ol>&#10;<aside class="wiki-admonition" role="note"><p><strong>Warning</strong></p><p><strong>Sync Time &amp; Performance:</strong></p>&#10;<ul>&#10;<li>Resyncing can take a significant amount of time*, depending on the age of your wallet and the number of transactions it contains.</li>&#10;<li>It is normal for your computer to experience <strong>high CPU usage</strong> during the resync process.</li>&#10;<li>Bisq <strong>may become unresponsive</strong> while syncing. Please be patient and let the process complete.</li>&#10;</ul>&#10;</aside>&#10;<figure class="wiki-source-image" id="source-image-1"><a href="../../media/wiki/74616f229fc23aca32ca8f2be50e9ee646cf0cc884f1df4da64965c936477ca6.png"><img alt="Click the 'RESYNC SPV WALLET' button under Settings &gt; Network Info." decoding="async" height="2306" loading="lazy" src="../../media/wiki/74616f229fc23aca32ca8f2be50e9ee646cf0cc884f1df4da64965c936477ca6.png" width="4096"></a><figcaption>Click the 'RESYNC SPV WALLET' button under Settings &gt; Network Info.<br><small>Historical full-size recovered source. <a href="../../recovered-media/">Provenance catalogue</a>.</small></figcaption></figure>&#10;<div>&#10;</div>&#10;<h3 id="from-the-file-system"> From the File System </h3>&#10;<p>Use this method if you cannot access the button within Bisq (e.g., if Bisq fails to start fully).</p>&#10;<ol>&#10;<li>Ensure Bisq is completely <strong>closed</strong>.</li>&#10;<li>Navigate to your <a href="../data-directory/">Bisq data directory</a>.</li>&#10;<li>Locate and <strong>delete</strong> the SPV chain file: `btc_mainnet/wallet/bisq.spvchain`</li>&#10;<li>Start Bisq and wait for it to fully load (it will begin the resync process).</li>&#10;<li><strong>Crucially, close Bisq completely and restart it a second time.</strong> Bisq will <em>not</em> prompt you for this second restart when using the manual method, but it is required for the wallet state to initialize correctly after the sync.</li>&#10;</ol>&#10;<aside class="wiki-admonition" role="note"><p><strong>Warning</strong></p><p><strong>Sync Time &amp; Performance:</strong></p>&#10;<ul>&#10;<li>As with the interface method, resyncing manually can take a <strong>significant amount of time</strong>, depending on wallet age and transaction count.</li>&#10;<li>Expect <strong>high CPU usage</strong> and potential Bisq <strong>unresponsiveness</strong> during the sync process. Be patient.</li>&#10;</ul>&#10;</aside>&#10;<h3 id="fix-an-incomplete-spv-resync"> Fix an Incomplete SPV Resync </h3>&#10;<p>Sometimes, especially on older or larger wallets, the SPV resync might hang or get interrupted. If restarting Bisq causes the resync to start over from 0% instead of resuming, you can try this:</p>&#10;<ol>&#10;<li>Ensure Bisq is completely <strong>closed</strong>.</li>&#10;<li>Navigate to the root folder of your <a href="../data-directory/#default-locations">Bisq data directory</a>.</li>&#10;<li>Locate and <strong>delete</strong> the file named `resyncSpv`. (This file typically only exists if a previous resync was interrupted).</li>&#10;<li><strong>Restart Bisq</strong>.</li>&#10;</ol>&#10;<p>It should now attempt to resume the SPV sync from where it previously left off.</p>&#10;<aside class="wiki-admonition" role="note"><p><strong>Note</strong></p><p>When resuming an incomplete sync this way, the Bisq UI might load and show balances <em>before</em> the background sync is fully complete. Your balance may appear incorrect until the process finishes. You can repeat steps 1-4 if the sync gets interrupted again, allowing it to complete in stages.</p>&#10;</aside>&#10;<h2 id="preventing-frequent-or-slow-resyncs-connect-to-your-own-node"> Preventing Frequent or Slow Resyncs: Connect to Your Own Node </h2>&#10;<p>If you find that Bisq frequently requires SPV file resyncs, or if the process consistently takes an extremely long time (especially with an older or high-transaction wallet), the most robust solution is to connect Bisq to your own Bitcoin full node.</p>&#10;<p>When connected to your local node, Bisq gets blockchain information directly and reliably, bypassing the need for the SPV synchronization process over the Tor network. This typically results in faster startups and eliminates most common sync-related issues and errors.</p>&#10;<p>For details on setting up a node and configuring Bisq to use it, please see:</p>&#10;<ul>&#10;<li><a href="../installing-your-own-bitcoin-node/">Installing your own Bitcoin node</a></li>&#10;<li><a href="../connecting-to-your-own-bitcoin-node/">Connecting to your own Bitcoin node</a></li>&#10;</ul>&#10;<p>While running a full node requires more resources (disk space, bandwidth), it offers the best performance, privacy, and stability when using Bisq.</p>&#10;</div>
