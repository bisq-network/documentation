<div class="wiki-recovered-article" lang="en"><p>The <strong>Compensation Maintainer</strong> handles announcements and issue triaging for compensation requests.</p>&#10;<span class="wiki-legacy-anchor" id="Issue" aria-hidden="true"></span><h2 id="issue"> Issue </h2>&#10;<a href="https://github.com/bisq-network/roles/issues/86" rel="noopener noreferrer">https://github.com/bisq-network/roles/issues/86</a>&#10;<span class="wiki-legacy-anchor" id="Team" aria-hidden="true"></span><h2 id="team"> Team </h2>&#10;<a href="https://github.com/orgs/bisq-network/teams/compensation-maintainers" rel="noopener noreferrer">@bisq-network/compensation-maintainers</a>&#10;<span class="wiki-legacy-anchor" id="Duties" aria-hidden="true"></span><h2 id="duties"> Duties </h2>&#10;<span class="wiki-legacy-anchor" id="Announce_BSQ-USD_exchange_rate" aria-hidden="true"></span><h3 id="announce-bsq-usd-exchange-rate"> Announce BSQ-USD exchange rate </h3>&#10;<p>Compensation requests use a <a href="https://github.com/bisq-network/proposals/issues/313" rel="noopener noreferrer">30-day volume-weighted average</a> to determine a BSQ/USD rate that discounts outliers. At the beginning of the cycle, the Compensation Maintainer should create a pinned issue with the title "BSQ rate for Cycle X is Y.YY USD per 1 BSQ".</p>&#10;<span class="wiki-legacy-anchor" id="Announce_request_submission_deadline" aria-hidden="true"></span><h3 id="announce-request-submission-deadline"> Announce request submission deadline </h3>&#10;<p>To allow time for team leads to discuss and review compensation requests, requests need to be ready for review 1 week before the end of current cycle's proposal phase.</p>&#10;<figure class="wiki-source-image" id="source-image-1"><a href="../../media/wiki/cff1be21338b53a6055edeaf828bfa02c99f41120504c367ed247c0f91a1f5ce.png"><img alt="Compensation board" decoding="async" height="352" loading="lazy" src="../../media/wiki/cff1be21338b53a6055edeaf828bfa02c99f41120504c367ed247c0f91a1f5ce.png" width="800"></a><figcaption>Compensation board<br><small>Historical thumbnail; original resolution not recovered. <a href="../../recovered-media/">Provenance catalogue</a>.</small></figcaption></figure>&#10;<p>Dates and reminders will be announced on a pinned issue at github <a href="https://github.com/bisq-network/compensation/issues" rel="noopener noreferrer">compensation repository</a>, the <a href="https://github.com/orgs/bisq-network/projects/20/" rel="noopener noreferrer">compensation board</a>, and the <a href="../events-calendar/">events calendar</a>.</p>&#10;<span class="wiki-legacy-anchor" id="Triage_incoming_requests" aria-hidden="true"></span><h3 id="triage-incoming-requests"> Triage incoming requests </h3>&#10;<p>The Compensation Maintainer watches the <a href="https://github.com/bisq-network/compensation/issues" rel="noopener noreferrer">compensation repository</a> and proceeds to triage:</p>&#10;<p>Incoming issues are categorized as <code class="wiki-source-code" id="source-code-1">In Progress</code> if they have <code class="wiki-source-code" id="source-code-2">[WIP]</code> at the beginning of the title or as <code class="wiki-source-code" id="source-code-3">In Review</code> if they don't. The Compensation Maintainer assigns <code class="wiki-source-code" id="source-code-4">In Review</code> issues to the appropriate team leads (or determine which team leads are responsible if it isn't obvious).</p>&#10;<p>As requests are submitted to the DAO (with txid posted in corresponding issues), the Compensation Maintainer should classify requests as <code class="wiki-source-code" id="source-code-5">Proposal Submitted</code>.</p>&#10;<p>This triage can be controlled from the Compensation board by:</p>&#10;<ul>&#10;<li>using the "Add cards" button on the board to triage new issues</li>&#10;<li>dragging and dropping existing issues to categories</li>&#10;<li>using the "Projects" section in the right sidebar of an issue's page</li>&#10;</ul>&#10;<span class="wiki-legacy-anchor" id="Archive_previous_cycle_requests_at_the_end_of_the_proposal_phase" aria-hidden="true"></span><h3 id="archive-previous-cycle-requests-at-the-end-of-the-proposal-phase"> Archive previous cycle requests at the end of the proposal phase </h3>&#10;<p>Once a cycle's proposal phase is over, the Compensation Maintainer should <a href="https://help.github.com/en/github/managing-your-work-on-github/archiving-cards-on-a-project-board" rel="noopener noreferrer">archive</a> all issues in the <code class="wiki-source-code" id="source-code-6">Done</code> column from the previous phase.</p>&#10;<p>The reason for waiting to archive these issues is so that contributors can easily see how many requests were made in the last cycle, quickly find their own request, and easily review which ones were accepted and rejected. Requests are archived in order to keep the board clean and make room for requests in the next cycle.</p>&#10;<span class="wiki-legacy-anchor" id="Close_current_cycle_requests_after_the_vote_reveal_phase" aria-hidden="true"></span><h3 id="close-current-cycle-requests-after-the-vote-reveal-phase"> Close current cycle requests after the vote reveal phase </h3>&#10;<p>When the reveal vote phase is complete, the Compensation Maintainer should take the following steps:</p>&#10;<ol>&#10;<li>Label each compensation request issue as <code class="wiki-source-code" id="source-code-7">was:accepted</code> or <code class="wiki-source-code" id="source-code-8">was:rejected</code> according to the vote result</li>&#10;<li>Close the issue with a comment indicating the request's outcome (e.g., "Closing as accepted" or "Closing as rejected")</li>&#10;</ol>&#10;<p>Once closed, the issues will automatically move to the <code class="wiki-source-code" id="source-code-9">Done</code> column of the board, where they remain for reference until they are archived at the end of the next cycle's proposal phase (see above).</p>&#10;<span class="wiki-legacy-anchor" id="Rights" aria-hidden="true"></span><h2 id="rights"> Rights </h2>&#10;<ul>&#10;<li>"Triage" access to the <a href="https://github.com/bisq-network/compensation/" rel="noopener noreferrer">compensation repository</a></li>&#10;</ul>&#10;<span class="wiki-legacy-anchor" id="Bonding" aria-hidden="true"></span><h2 id="bonding"> Bonding </h2>&#10;<p>N/A</p>&#10;</div>
