<div class="wiki-recovered-article" lang="en"><p><strong>Switching to a new data directory</strong> can help you start with Bisq anew: fresh wallet, new onion address, new keys, etc. It's a sort of "factory reset" that makes it like you're starting Bisq for the first time.</p>&#10;<p>Upon creating a new data directory, you can restore various parts of a previous data directory (e.g., aged and signed payment accounts).</p>&#10;<p>If you instead wish to only obtain a new wallet, while preserving every other element of your data directory, you can <a href="../create-a-new-wallet-for-your-data-directory/">create a fresh wallet in the same data directory</a>.</p>&#10;<span class="wiki-legacy-anchor" id="Why_switch_to_a_new_data_directory?" aria-hidden="true"></span><h2 id="why-switch-to-a-new-data-directory"> Why switch to a new data directory? </h2>&#10;<p>It's a good idea to switch to a new data directory every so often.</p>&#10;<ul>&#10;<li><strong>Performance</strong> - Bisq uses bitcoinj, an SPV library that is not built for high performance, so wallets get increasingly large with every transaction. Over time, wallet corruption becomes increasingly likely and overall performance deteriorates (e.g., longer startup times).</li>&#10;<li><strong>Stability</strong> - The internal wallet database can get corrupted in certain situations, leading to failed take-offer attempts or failed payouts.</li>&#10;<li><strong>Privacy</strong> - Active traders using the same onion address for extended periods of time can leak quite a bit of information, since that same onion address is connected to each subsequent offer (see <a href="../local-reputation/">local reputation</a>).</li>&#10;</ul>&#10;<p>In addition, switching to a new data directory can sometimes be the only way to work around <a href="../troubleshooting-wallet-issues/">unusual wallet corruption issues</a>.</p>&#10;<span class="wiki-legacy-anchor" id="Make_sure_you&#x27;re_ready_to_switch" aria-hidden="true"></span><h2 id="make-sure-you-re-ready-to-switch"> Make sure you're ready to switch </h2>&#10;<span class="wiki-legacy-anchor" id="Ensure_your_existing_data_directory_is_backed_up" aria-hidden="true"></span><h4 id="ensure-your-existing-data-directory-is-backed-up"> Ensure your existing data directory is backed up </h4>&#10;<p><a href="../backing-up-application-data/#back-up-the-entire-bisq-data-directory">See how here</a>. Be sure to also do a <a href="../backing-up-application-data/#back-up-payment-accounts">payment account export</a> to make importing payment accounts easier.</p>&#10;<span class="wiki-legacy-anchor" id="Ensure_you_have_no_open_offers,_trade,_or_disputes" aria-hidden="true"></span><h4 id="ensure-you-have-no-open-offers-trade-or-disputes"> Ensure you have no open offers, trade, or disputes </h4>&#10;<p>This is paramount because <strong>you will become unreachable and unable to respond after switching to a new data directory.</strong> If you don't want to wait for an open offer to be taken, you can delete it, but you will lose the maker fee.</p>&#10;<span class="wiki-legacy-anchor" id="Send_funds" aria-hidden="true"></span><h2 id="send-funds"> Send funds </h2>&#10;<p>You will need to get your funds to the new Bisq instance somehow.</p>&#10;<p>There are a handful of methods to do this, depending on your situation.</p>&#10;<ol>&#10;<li>Send funds to an external wallet with a withdrawal from <code class="wiki-source-code" id="source-code-1">Funds</code> &gt; <code class="wiki-source-code" id="source-code-2">Send Funds</code>, and then send those funds to the new Bisq instance once you've created it (note: you can set withdrawal transaction fees in <code class="wiki-source-code" id="source-code-3">Settings</code> &gt; <code class="wiki-source-code" id="source-code-4">Preferences</code>).&#10;<ul>&#10;<li>Variation: Use the <a href="../emergency-wallet/">Emergency Wallet Tool</a> (<code class="wiki-source-code" id="source-code-5">Cmd/Ctrl</code> + <code class="wiki-source-code" id="source-code-6">E</code>) to withdraw funds if standard withdrawal isn't working.</li>&#10;</ul></li>&#10;<li>Restore your wallet from seed in another bitcoin wallet like Electrum, and send funds to the new Bisq instance once you've created it. This method is <strong>not</strong> recommended if you have any BSQ funds in your wallet. See <a href="../restoring-your-wallet-from-seed/#restoring-to-a-non-bisq-wallet">derivation path and other details here</a>.</li>&#10;<li>Send funds directly from old Bisq instance to new Bisq instance (advanced).&#10;<ol>&#10;<li>Start Bisq.</li>&#10;<li>Start another instance of Bisq from the command line, specifying a new data directory with the <code class="wiki-source-code" id="source-code-7">appName</code> option. See <a href="../running-from-the-command-line/">how to run Bisq from the command line here</a>.&#10;<ul>&#10;<li>macOS example command: <code class="wiki-source-code" id="source-code-8">/Applications/Bisq.app/Contents/MacOS/Bisq --appName=Bisq-new</code></li>&#10;<li>Name of the new directory doesn't matter. <code class="wiki-source-code" id="source-code-9">Bisq-new</code> was used above as an example, but you can call it whatever you like, since it's just a temporary placeholder. You'll be changing it back to "Bisq" anyway.</li>&#10;</ul></li>&#10;<li>Wait for this new instance of Bisq to start and finish loading and syncing.</li>&#10;<li>Once it has, send your funds from your old Bisq instance to your new one.</li>&#10;</ol></li>&#10;</ol>&#10;<span class="wiki-legacy-anchor" id="Create_new_data_directory" aria-hidden="true"></span><h2 id="create-new-data-directory"> Create new data directory </h2>&#10;<p>If you used methods 1 or 2 in the previous step:</p>&#10;<ol>&#10;<li>Close Bisq.</li>&#10;<li>Delete (or rename) the <code class="wiki-source-code" id="source-code-10">Bisq</code> data directory (see <a href="../data-directory/">default locations for your operating system here</a> <small class="wiki-link-gap">[section not recovered: Operating system defaults]</small>).</li>&#10;<li>Start Bisq again. Bisq will create a new data directory with a new wallet, new Tor state, etc.</li>&#10;<li>Send funds from external wallet into Bisq.</li>&#10;</ol>&#10;<p>If you used method 3 in the previous step:</p>&#10;<ol>&#10;<li>Make sure <em>both</em> Bisq instances are closed.</li>&#10;<li>Delete (or rename) the original <code class="wiki-source-code" id="source-code-11">Bisq</code> data directory.</li>&#10;<li>Rename the newer data directory to <code class="wiki-source-code" id="source-code-12">Bisq</code>.</li>&#10;<li>Start Bisq normally. Your balance should reflect the BTC you sent to it previously.</li>&#10;</ol>&#10;<span class="wiki-legacy-anchor" id="Migrate_data_from_backup" aria-hidden="true"></span><h2 id="migrate-data-from-backup"> Migrate data from backup </h2>&#10;<p>If you'd like to restore payment accounts and/or your onion address (e.g., <a href="../local-reputation/">local reputation</a>), <a href="../restoring-application-data/">see how in this article</a>.</p>&#10;</div>
